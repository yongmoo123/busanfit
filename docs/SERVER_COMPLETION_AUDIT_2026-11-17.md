## 이번에 보완한 서버 작업

처음 별도 로컬 브랜치에 모은 보완을 사용자 요청에 따라 기존 PR #48·#49·#50·#54·#55·#56에 정상 추가 커밋/병합으로 반영했다. 새 PR과 force push는 사용하지 않는다. 기반 기능 범위와 가상 검증·PM 비활성 조건을 유지한다.

1. **본인 PR #12 세션 종료를 현재 스택에 연결.** sessions 라우트·DELETE 테스트·HTTP 예시와 로그 인계 문서를 재사용하고 최신 SessionStore에 멱등 delete를 결합했다. OpenAPI/계약 검사에 DELETE를 추가해 총6 operations이다. 삭제 후 profile/chat/course/finish_read가 세션을 부활시키지 않는지 확인한다.
2. **실제 PR #41 SQLite 구현을 API 스레드에 연결.** db/geo/memory/schema/settings/sqlite_repository 및 공통 Repository 테스트를 변경 없이 선택 재사용했다. 공통 place 모델·ID·Protocol은 기존 #23과 같다. 출처 commit `451b3f0980aeabf89116d2f76092808a5e433b62`이며 PR #41 병합 완료로 간주하지 않는다.
3. **호출마다 연결하는 어댑터.** application/sqlite_adapter.py는 SQLite 연결을 생성한 스레드 안에서 사용·종료한다. 기존 Repository에 위임하며 SQL·검색 정책·이동시간 계산을 작성하지 않았다. DB가 없으면 빈 파일을 만들지 않고 실패하며 인자 오류는 연결 전 ValueError다. 일반 앱에는 자동 연결하지 않는다.
4. **실제 SQLite 코드 + 가상행의 HTTP 통합.** 일반·휠체어·유모차·부상에서 세션→조건→코스→가상 설명→상세→종료를 검사했다. 두 출처 합치기·동시 읽기·깨진 DB500·삭제 후410도 포함한다. SQLite를 사용했다는 사실은 실제 해운대 데이터를 검증했다는 뜻이 아니다.
5. **늦은 추출기 예외 보완.** chat의 외부 추출기가 예외를 던져도 최신 revision·삭제 상태를 먼저 재검사하고, 일반 오류는 정적500으로 처리해 예외 원문이 서버 미들웨어 로그로 나가지 않게 했다. 취소는 삼키지 않는다.
6. **한 명령의 근거 수집.** evaluation/server/run.py가 전체 pytest·계약·참고 문서·diff 검사, 규칙 추출 참고 평가, 코스/설명/제안/동행의 가상 평가를 모은다. 보고서에는 집계만 저장하며 세션 ID·원문·오류 traceback은 쓰지 않는다.

통합 pytest **729 passed**, 기존 Starlette/httpx 경고1건. 계약6 operations·31 schemas·20 JSON examples·15 정책 사례/negative controls·참고 문서 동기화 통과. 729개는 본인510개에 선행 Repository/종료 테스트와 추가 통합 검사를 합친 수이며 전부 새로 작성한 테스트라는 뜻이 아니다. 최종 커밋 기준 결과는 [서버 검증 JSON](../evaluation/server/results/offline-2026-11-17.json)을 따른다.
