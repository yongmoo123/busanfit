# FR-018 동행별 카테고리 가중치 제안 — PM 검토 대기

2026-11-17, 김영무 / 이슈 #27. **PROPOSAL, pmApproved=false. 일반 경로 비활성.** 이 문서와 설정 파일은 확정 결정이 아니며 DECISIONS에 새 정책을 확정 기록하지 않습니다.

## 제안 표

설정: `config/companion-weights.proposal.json`, version `draft-2026-11-17`.

| 동행 | CAFE | FOOD | EXHIBITION | ATTRACTION | PARK | SHOPPING | OTHER |
|---|---:|---:|---:|---:|---:|---:|---:|
| COUPLE | 3 | 1 | 2 | 1 | 1 | 0 | 0 |
| FAMILY | 0 | 0 | 3 | 3 | 3 | 0 | 0 |
| FRIENDS | 1 | 0 | 0 | 3 | 2 | 1 | 0 |
| SOLO | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| OTHER | 0 | 0 | 0 | 0 | 0 | 0 | 0 |

가족의 관광·전시·공원 우대 방향만 DEC-013에 근거합니다. 그 수치와 나머지 매핑은 가상 비교용 제안입니다. 연인의 카페/전시, 친구의 관광/공원 등은 PM이 검토할 **카테고리 선호 초안**이며 실제 장소가 분위기·야경·활동성을 갖췄다는 판정이 아닙니다. 혼자·기타·동행 미입력은 근거 부족으로 중립입니다. 0점은 후보 제외를 뜻하지 않습니다.

합산: `2 × 기존 SOFT 실내/실외 일치(0 또는 1) + 1 × 동행 카테고리 값`. 따라서 SOFT 실내 선호는2점, 동행 선호는0~3점입니다. 예를 들어 연인의 실내 전시는4점, 실외 카페는3점입니다. HARD 실내 조건은 점수가 아니라 기존 필터·검증기로 처리합니다. 두 계수도 확정값이 아니며 함께 PM 확인 대상입니다.

## 반영하지 않는 정보

- 가격은 UNKNOWN이므로 가성비·무료 여부 점수 없음.
- 현재 PlaceRecord에는 분위기·야경·활동성 태그가 없으므로 이름·개요에서 추측하지 않음.
- 정원·그룹 이용 가능 근거가 없어 인원수는 중립. 인원수를 하드 필터로 쓰지 않음.
- 영유아 여부는 점수에 쓰지 않고 기존 #21의 유모차 HARD 정규화·USER 선택 우선을 유지.
- 미입력·기타 동행을 특정 유형으로 추정하지 않음. HARD 동행은 기존 API의 미지원 처리 유지.

## 가상 비교

같은7개 후보, 동일한 체류60분·이동5분·거리·영업시간, 135분 시간창을 사용합니다. 기준선은 모든 동행에서 OTHER/CAFE입니다.

| 동행 | 제안 적용 시 선택 | 비고 |
|---|---|---|
| 연인 | CAFE / EXHIBITION | 가상 점수5 |
| 가족 | EXHIBITION / ATTRACTION | 합계6, PARK도3점이며 동점은 기존 ID 순서 |
| 친구 | ATTRACTION / PARK | 합계5 |
| 혼자·기타·미입력 | OTHER / CAFE | 기준선 유지 |

이는 선호 품질·실제 관광 적합성 검증이 아닙니다. 실제 데이터에서 필요한 태그·가중치·후보 편중과 사용자 경험은 후속 검토합니다. 기존 스케줄러의 방문 수 우선/부상 시 장소 수 축소·체류 확대·시간/이동 규칙은 바꾸지 않았습니다. 스케줄러는 제한된 탐색이므로 전역 최적해나 모든 상황에서의 최대 방문 수를 보장하지 않습니다.

## PM 확인할 항목과 활성화 조건

1. 동행별 카테고리 매핑·수치·중립 정책과 실내 선호 대비 계수.
2. 분위기/야경/활동성·인원 적합성 데이터가 없을 때 위 제한을 유지할지.
3. 실제 데이터 검증 이후 일반 경로 활성화 시점.

현재 설정을 읽는 함수는 미승인 PROPOSAL만 허용하며 pmApproved=true로 바꾸면 거절합니다. 플래그를 바꿔 일반 앱을 켜는 구조가 아닙니다. **PM 확인 기록과 별도의 검토된 활성화 변경**이 있어야 일반 CourseService에 scorer를 주입할 수 있습니다. 이번 작업은 승인 요청을 게시하거나 일반 경로를 활성화하지 않습니다.
