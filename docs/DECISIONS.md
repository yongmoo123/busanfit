- "반영 위치"의 체크는 해당 문서·코드가 실제로 수정되어 병합된 뒤에만 표시한다.

## DEC-001 기본 이동수단
- 날짜: 2026-11-05 · 결정자: 김세민(PM)
- 결정:
  - 최종 기본 이동수단은 **대중교통**(SRS FR-005 유지).
  - 스프린트 2는 **도보(WALK)만 지원**한다. 이 기간 기본값은 WALK(`source=DEFAULT`)로 카드에 표시하고, `capabilities`로 지원 범위를 화면에 알린다.
  - 스프린트 3에 대중교통(PUBLIC)을 추가하면서 기본값을 대중교통으로 바꾼다. 이동수단 값 이름은 계약(`WALK`/`PUBLIC`/`CAR`)을 따른다.
  - 도보(WALK) 검색 반경은 **권역 중심 기준 1.5km**로 하고 설정값으로 관리한다. 데이터 확인 후 조정한다.
  - **자차(CAR)**는 스프린트 3에 대중교통 다음 순서로 추가한다. 주차장 표시(FR-017)와 자차 검색 반경 5km를 함께 묶는다. **스프린트 3 일정이 빠듯하면 가장 먼저 축소**한다.
  - 스프린트 2에서는 자차 표현도 추출하되, `capabilities` 기준 미지원으로 안내한다.
- 이유: 대중교통 모드는 역 정보·역간 소요시간 데이터가 필요해 첫 연결을 늦춘다. 한 권역 안에서는 도보만으로 전체 흐름(채팅→카드→코스→지도)을 먼저 완성할 수 있다.

## DEC-005 DB: SQLite
- 날짜: 2026-11-05 · 결정자: 김세민(PM)
- 결정:
  - DB는 **SQLite**를 사용한다. PostgreSQL·PostGIS·Docker DB 컨테이너는 사용하지 않는다.
  - 좌표는 위도·경도 숫자 컬럼(`latitude`, `longitude` REAL)으로 저장한다.
  - 반경 검색은 Repository 안에서 ① 위경도 사각형으로 1차 필터(일반 인덱스) ② 하버사인 거리로 2차 필터 순서로 처리한다.
  - 좌표계 변환(EPSG:5174→WGS84)은 적재 시 `pyproj`로 한 번만 수행한다.
  - JSON 컬럼(`open_hours`, `raw` 등)은 TEXT에 JSON 문자열로 저장한다.
  - 설계 문서의 컬럼 타입은 SQLite 실제 타입(INTEGER, REAL, TEXT)으로 적고, 원래 의미는 설명에 적는다. 예: 불리언 → INTEGER "0/1 불리언", 시각 → TEXT "ISO 8601 시각", JSON → TEXT "JSON 문자열", UUID → TEXT "UUID 문자열".
  - DB 파일은 커밋하지 않는다(.gitignore의 `*.sqlite*`, `*.db`). 누구나 같은 적재 명령으로 재생성할 수 있어야 한다.
  - 코스 엔진은 DB를 직접 호출하지 않고 **PlaceRepository 인터페이스**만 사용한다. 인터페이스는 이찬용·김영무가 스프린트 1 안에 합의한다.
- 이유: 부산 장소 데이터는 수천~1만 건 규모로 예상되어 공간 인덱스의 성능 이점이 없다(전체 탐색도 수 ms). 설치가 필요 없어 팀 전원의 로컬 환경·CI·배포가 단순해진다. 기존 ADR-007에 대안으로 기록되어 있던 안이다.
- 트레이드오프: 공간 질의를 직접 구현해야 함(약 30줄), 쓰기 동시성이 약함(읽기 전용 서비스라 영향 없음), 데이터 갱신은 새 DB 파일 생성 후 교체 방식.
- 영향: FR-007, FR-017, FR-020, NFR-001
- 반영 위치:
  - [ ] SRS 2.3 운영 환경 Database 줄
  - [ ] SDD 1.3 Performance("PostGIS 공간 인덱스" 문구), 3 COMP-10 의존성, 5.1 ER 캡션, 10.1 배포(db 컨테이너 제거), 12 추적표 NFR-001
  - [ ] SDD 2.2 — ADR-007을 "대체됨(ADR-008, DEC-005)"으로 표시하고 ADR-008(SQLite) 추가
  - [ ] SDD 5.2 — 모든 타입을 SQLite 타입으로 변경(GEOGRAPHY→latitude·longitude REAL, JSONB→TEXT 등), 원래 의미는 설명 칸에
  - [ ] SDD 그림 2-1(아키텍처)·5-1(ER)·10-1(배포)을 Mermaid로 다시 그림 — 원본 `docs/diagrams/`, PNG `docs/images/`
  - [ ] 계획서 6장 기술 스택 DB 행

## DEC-006 건강 정보의 LLM 전달 범위
- 날짜: 2026-11-05 · 결정자: 김세민(PM)
- 결정:
  - **사용자가 쓴 말을 해석하는 호출**(조건 추출, 수정 의도 해석)은 사용자 원문 전달을 허용한다(원문 없이는 해석할 수 없음).
  - **시스템이 만든 데이터를 넘기는 호출**(코스 요약, 추천 이유 생성)에는 건강 정보를 범주값(wheelchair, stroller, injury 등)으로만 넣는다. 수정 의도 해석 때 메시지와 함께 보내는 코스 요약도 범주값만 쓴다.
  - 개발 중에는 가상 시나리오만 입력한다. 시연은 입력을 학습에 사용하지 않는 유료 API로 진행한다.
  - 원문·프롬프트·응답의 건강 정보는 로그에 남기지 않는다.
- 이유: SRS AI-REQ-03·SDD 9장의 "범주값으로만 전달"은 사용자 원문을 해석해야 하는 호출(조건 추출, 수정 의도 해석)과 동시에 성립할 수 없다.
- 영향: AI-REQ-03, NFR-003, NFR-005, FR-015
- 반영 위치:
  - [ ] SRS AI-REQ-03 문구 수정
  - [ ] SDD 9 "로그에 민감정보를 남기지 않음" 마지막 문장 수정
  - [ ] SDD 7.2 LLM(수정 해석) 입력 — 코스 요약은 범주값만

## DEC-007 LLM 실패 처리
- 날짜: 2026-11-05 · 결정자: 김세민(PM)
- 결정:
  1. LLM 지연(10초 초과)·스키마 불일치 시 1회 재시도한다.
  2. 재실패하면 **키워드 규칙 파서**로 추출한다.
  3. 파서가 확신하지 못한 항목 중 **하드 제약 판단에 쓰이는 항목(지역, 시간, 이동제약, 제외 카테고리, 예산 상한)**은 기본값을 넣지 않고 `UNSET`으로 두며, 조건 카드에서 사용자에게 확인을 요청한다. **소프트 항목은 기본값(`source=DEFAULT`)**을 넣는다. 응답 `warnings`에 대체 처리 사실을 알린다. 지연(Timeout) 시 사용자 메시지는 "응답이 늦어 일부 조건을 확인하지 못했어요. 조건 카드에서 확인해 주세요."로 한다.
  4. 파서도 지역·시간을 추출하지 못하면 **503 AI_UNAVAILABLE**을 반환하고 카드 직접 입력을 안내한다. (기존 값을 포함해 지역·시간이 **둘 다** 없을 때만 해당 — DEC-021에서 명확화)
  5. 어떤 경우에도 하드 제약을 지운 채 일반 코스를 만들지 않는다. 추천 이유 생성 실패는 템플릿 문장으로 대체한다.
- 이유: SRS NFR-002(규칙 기반 대체)와 계약(503, 하드 조건 삭제 금지)을 함께 만족한다. 이동제약을 놓친 채 일반 코스를 주는 것이 이 서비스에서 가장 위험한 실패다.
- 영향: NFR-002, AI-REQ-02, FR-002, FR-006
- 반영 위치:
  - [ ] SRS UC-001 대안 흐름 2a·3b
  - [ ] SDD 7.4 — Timeout 행 메시지("기본 설정으로 코스를 만들었어요" → 3항의 문구), 스키마 불일치 행("해당 필드 기본값 적용" → 하드 판단 항목은 UNSET, 소프트 항목은 기본값)
  - [ ] SDD 8 ERR-002
  - [ ] API 계약 §7 — 503 조건 명시

## DEC-015 무장애 정보 연결과 이동제약 판정
- 날짜: 2026-11-09 · 결정자: 김세민(PM) · 계기: 이슈 #7 질문 7, 정할 것 3
- 결정:
  - **연결**: 장소 기본 정보와 무장애 정보는 원본 ID(`source_place_id`)로 짝짓는다. 짝이 없으면 `accessibility` 행을 만들지 않고 API에서 `UNKNOWN`으로 내보낸다. 해운대 표본으로 두 서비스의 ID 일치를 확인하고 매칭률을 보고한다.
  - **항목값**(휠체어·유모차·엘리베이터·장애인 화장실): 원문에 명시적으로 가능하면 true, 명시적으로 불가하면 false, 언급이 없거나 모호하면 null(보수적 판정). 원문은 `raw`에 보존하고, `evidence`는 `raw`와 `source_id`로 만든다.
  - **하드 제약 판정은 항목별로 한다**: `WHEELCHAIR` → `wheelchair = true`만 통과, `STROLLER` → `stroller = true`만 통과. null은 기본 후보에서 제외하고 "정보 없는 장소 포함" 제안 대상(FR-013)으로 둔다. false는 제외한다.
  - **등급은 표시용 요약**이다: 정보 없음 → `UNKNOWN`, 휠체어·유모차 모두 false → `UNSUITABLE`, 둘 중 하나라도 true → `VERIFIED`. 등급만으로 하드 제약을 판정하지 않는다.
- 이유: 등급 하나로 판정하면 "유모차는 되지만 휠체어는 안 되는 장소"가 휠체어 사용자에게 추천될 수 있다. 계약이 이미 항목 4개를 갖고 있다.
- 영향: FR-008, FR-013, FR-018, AI-REQ-05, NFR-009
- 반영 위치:

## DEC-016 부상(INJURY) 처리
- 날짜: 2026-11-09 · 결정자: 김세민(PM)
- 결정: 스프린트 2는 계약을 바꾸지 않고, 이동제약에 `INJURY`가 있으면 다음 고정 규칙을 적용한다.
  1. 이동시간 계산 시 보행 속도를 낮춘다. **초기값: 일반 4km/h → 부상 3km/h**
  2. 장소 사이 구간당 도보시간이 **초기값 10분**을 넘으면 그 구간을 코스에 넣지 않는다(HARD).
  3. 계단 회피(HARD)는 장소 단위로 `wheelchair = true`를 대리 지표로 판정한다. null은 `UNKNOWN`(FR-013 제안 대상), false는 제외.
  4. 이동 경로의 계단·경사는 데이터가 없어 확인할 수 없으므로, 코스 `warnings`에 확인하지 못했다고 알린다.
  5. 장소 수를 줄이고 체류를 늘리는 쪽으로 점수를 준다(SOFT).
  - 수치(1·2)는 설정값이다. 담당자(이찬용)가 데이터 확인 후 조정할 수 있으며, PR 본문에 근거를 적고 김영무 리뷰를 받은 뒤 이 항목의 값을 갱신한다. 크게 바꾸면 팀 채팅에 공유한다.
  - 후보가 부족해도 계단 조건을 몰래 빼지 않는다. "계단 조건을 빼고 다시 만들까요?"처럼 사용자가 선택하게 한다.
  - 사용자별 최대 도보시간·계단 회피 켜기/끄기는 스프린트 3에 계약 확장을 검토한다.
- 이유: 계약의 이동제약에는 `INJURY` 값만 있고 세부 항목이 없다. 보행 경로 데이터가 없어 확인 가능한 것은 장소의 무장애 정보뿐이다. 휠체어 접근 가능 여부는 계단 없이 진입 가능한지에 대한 보수적인 지표다.
- 영향: FR-008, FR-009, SRS 표 3-1 장애요소, SRS 2.5
- 반영 위치:
  - [ ] SDD 1.4 또는 7.3에 부상 규칙 추가 (PM)
  - [ ] 보행 속도·최대 도보시간 설정값과 이동시간 반영 (이찬용), `INJURY` 추출·검증·경고 (김영무), 규칙 안내·계단 조건 해제 제안 화면 (배진호)

## DEC-019 미지원 이동수단 응답
- 날짜: 2026-11-09 · 결정자: 김세민(PM) · 계기: 이슈 #6 정할 것 1, PR #13 제안 1 (수정 승인)
- 결정:
  - **조건 카드(PUT)**: capabilities에 없는 이동수단은 `422 UNSUPPORTED_CONSTRAINT`(`field: transport`)로 거절하고, 요청 전체를 저장하지 않는다(기존 프로필·revision·TTL 유지). 오류 details에 입력 원문을 복사하지 않는다. (제안 그대로)
  - **채팅(chat)**: 메시지 전체를 거절하지 않는다. 함께 이해한 다른 조건(지역·시간·동행 등)은 정상 반영하고, 미지원 이동수단은 **반영하지 않은 채** 질문(`questions`, `field: transport`, 예: "자차는 아직 지원하지 않아요. 도보로 코스를 만들까요?")과 `warnings`로 안내한다. 사용자가 수락하면 지원되는 값을 `source=USER`로 저장한다. 질문 수 한도(최대 2개)를 지킨다.
  - 어느 경우에도 사용자가 요청한 값을 지원되는 값으로 몰래 바꾸지 않는다. 이동수단을 말하지 않은 경우의 기본값(DEC-001)과 명시적 미지원 요청을 구분한다.
- 이유: 카드에서는 필드 단위 거절로 잃는 입력이 없다. 채팅에서 422로 거절하면 한 단어 때문에 지역·시간 등 나머지 정보를 모두 잃는다. DEC-001의 "자차 표현도 추출하되 미지원으로 안내"와도 맞다. 질문·경고는 기존 계약 형식이라 새 필드가 필요 없다.
- 영향: FR-001, FR-004, FR-006, DEC-001

## DEC-020 이동제약 사용자 선택 우선
- 날짜: 2026-11-09 · 결정자: 김세민(PM) · 계기: 이슈 #6 정할 것 2, PR #13 제안 2 (승인 + 경고 추가)
- 결정: PR #13 제안 2를 그대로 승인한다.
  - 이동제약이 null/UNSET이고 영유아 동반이면 `[STROLLER]`/HARD/DEFAULT (DEC-002).
  - **`source=USER`인 이동제약이 우선**한다. USER의 `[]`(제약 없음)는 유지하고, USER의 비어 있지 않은 목록에도 유모차를 자동 추가하지 않는다.
  - 카드에서 유모차만 해제하면 다른 제약은 유지하고 USER로 저장한다. 해제 상태는 이후 대화에서 자동 재적용하지 않는다. 사용자가 유모차를 명시적으로 요청하면 USER/HARD로 추가한다.
  - 이동제약을 null/UNSET으로 초기화하면(명시적 `[]`와 구분) 영유아 동반 시 기본값 적용 대상으로 돌아간다. 영유아 동반을 취소하면 DEFAULT로 들어간 유모차만 제거한다.
  - **추가:** 사용자가 고른 이동제약 목록에 유모차가 없는데 영유아 동반이면, 응답 `warnings`에 "유모차 조건은 자동으로 넣지 않았어요. 필요하면 조건 카드에서 추가해 주세요."를 붙인다. 질문이 아니므로 질문 한도를 쓰지 않는다.
- 이유: 이동제약의 출처(source)는 목록 전체에 하나라 USER와 DEFAULT를 섞을 수 없다. 다만 부상(INJURY)과 영유아 동반이 겹치면 유모차 조건이 빠진 것을 사용자가 모를 수 있어, 하드 제약을 몰래 완화하지 않도록 경고로 알린다.
- 영향: FR-005, FR-006, FR-018, DEC-002
- 반영 위치:
  - [ ] API 계약 §4 — 자동 유모차 문구 교체, USER 우선·초기화 의미, 경고 코드 (김영무, 이슈 #6)
  - [ ] 구현·테스트 (김영무), 기본값 배지·해제·경고 표시 (배진호)

## DEC-021 503·NEEDS_INPUT 판정과 미확인 하드 조건
- 날짜: 2026-11-09 · 결정자: 김세민(PM) · 계기: PR #13 제안 3 (판정표 승인, 표현 방식 수정)
- 결정:
  - **판정표 (제안 그대로 승인)**
    | 상황 | 응답 |
    |---|---|
    | LLM 정상, 지역·시간 미입력 | 200 NEEDS_INPUT, 부족 항목 질문(최대 2개) |
    | LLM 재실패 → 파서, 기존 값을 포함해 지역·시간 **둘 다** 없음 | 503 AI_UNAVAILABLE, 기존 프로필·revision·대화·TTL 유지 |
    | LLM 재실패 → 파서, 지역·시간 중 하나만 확보 | 200 NEEDS_INPUT, 부족 항목 질문 + 대체 처리 안내 |
    | LLM 재실패 → 파서, 둘 다 확보 | 일반 검증 결과(200 또는 422) |
    - 200은 세션·revision·요청 제한·지원 범위 검증을 통과한 경우에 한하며 409·410·422·429를 덮어쓰지 않는다.
  - **보호 규칙 (제안 그대로 승인)**: 새 메시지에서 언급하지 않은 기존 값은 유지한다. 파서의 UNSET으로 기존 USER/HARD 조건을 덮어쓰지 않는다. 확인되지 않은 하드 조건이나 해석하지 못한 변경 의도가 남아 있으면 코스를 생성하지 않는다.
  - **표현 방식 (수정)**: "확인 필요"를 위한 새 상태·필드를 만들지 않는다.
    - `NEEDS_INPUT`의 정의를 "생성 필수 정보 부족 **또는 확인되지 않은 하드 조건·변경 의도가 남음**"으로 넓힌다.
    - 확인할 항목은 `questions`(`field` 지정, 최대 2개씩)로 묻고, 대체 처리·미확인 변경은 `warnings`의 `code`로 알린다(예: `AI_FALLBACK`, `UNCONFIRMED_CHANGE` — 코드 이름은 김영무가 확정).
    - 코스 생성은 READY에서만 가능하므로 확인 전 생성이 자동으로 막힌다.
  - DEC-007 4항의 "지역·시간을 추출하지 못하면"은 "기존 값을 포함해 지역·시간이 둘 다 없으면"으로 해석한다.
- 이유: 계약의 질문(`field`)·경고(`code`)로 미확인 상태를 충분히 표현할 수 있어, 계약 구조를 바꾸지 않고 스프린트 2 일정 안에서 안전 원칙(미확인 하드 조건으로 코스를 만들지 않음)을 지킬 수 있다.
- 영향: FR-002, FR-004, NFR-002, AI-REQ-02, DEC-007
- 반영 위치:
  - [ ] API 계약 §4 NEEDS_INPUT 정의, §7 503 판정표, 경고 코드 목록 (김영무, 이슈 #6)
  - [ ] SDD 7.4·8 ERR-002에 판정표 반영 (PM)
  - [ ] 구현·테스트 (김영무), 질문·경고·503 직접 입력 안내 화면 (배진호)
