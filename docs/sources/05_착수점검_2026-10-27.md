# 부산핏 착수 점검 기록

날짜: 2026-10-27 (Asia/Seoul)
상태: **현황 점검 완료 / 아래 실행 계획은 제안 / 팀의 신규 기술·범위 결정 없음**

## 1. 첫 작업 판단과 실제 수행

첫 작업은 **구현 기준과 실행 가능한 자산을 확인하고, 계약 검증 기준선을 확보하는 것**으로 정했다. 현재 제공된 폴더는 실행 서버가 아닌 계약 묶음이다. 도보 기본값·첫 권역·지원 범위 등의 초안을 확정 사항으로 구현하면 원본 SRS와 어긋날 수 있으므로, 이 결정에 의존하지 않는 검증과 작업 분해부터 수행했다.

확인한 근거:
- 01번: 현재 서비스 정의, FR-001~020, 품질 기준 및 원본 부록.
- 02번: 구성요소 책임, 데이터 확인 항목, 구현 전 합의할 쟁점.
- 03번: 첫 회의·팀원별 첫 주 작업·GitHub 운영·첫 주 검수 기준. 일정은 제안이다.
- 04번 및 개발 폴더 API_CONTRACT.md: 공통 API 초안, revision·상태·미확인 값·예시 사용 순서.

현황은 제공된 두 폴더에 한정하며, 팀의 다른 저장소에 구현이 없는지는 확인하지 않았다.

| 항목 | 확인 결과 |
|---|---|
| 개발 자산 | openapi.json, API_CONTRACT.md, example-index.json, 예시 JSON 20개, validate_contract.py |
| 앱 구현·실데이터 | 제공 폴더에서 서버·프론트·DB·실제 데이터 적재 코드 및 의존성 명세를 찾지 못함 |
| Git | 현재 개발 폴더에서 git status 실패: Git 저장소 아님. 원격 URL 미제공 |
| 실행 환경 | 기본 python 명령은 WindowsApps 실행 별칭에서 실패. 번들 Python 3.12.14로 검사 실행 성공 |
| 기존 계약 검사 | PASS: 5 operations, 31 schemas, 20 JSON examples. 참조·내장 예시·시간 합계·출처 연결·잘못된 입력 3개 거절 검사 |
| 참고 문서 동기화 | validate_source_sync.py 추가·실행. 04번 문서의 31개 스키마·20개 예시 JSON과 개발 파일의 값 일치 |
| 한계 | 전체 OpenAPI 표준 검증, 문서 산문 자동 비교, HTTP 통합, LLM, 실DB, 지도, 성능·개인정보 폐기 시험은 수행하지 않음 |

모든 기존 예시 장소·출처는 가상이다. 실제 부산 데이터 확보 건수로 집계하지 않는다. 모델·가격·데이터/API 이용조건의 외부 확인도 이번 점검 범위에는 포함하지 않았다.

## 2. 결정이 필요한 차이와 영향

아래는 확정 결정이 아닌 검토 목록이다. 기존 API 경로·필드·타입·상태·revision 규칙은 변경하지 않았다.

| ID / 상태 | 원본과 초안의 차이 | 확정 시 반영할 곳·검증 | 합의 전 가능한 작업 |
|---|---|---|---|
| D-01 미합의 | SRS 기본 이동수단 대중교통, 첫 주 예시 WALK | FR-005·007·009, 기본값 설계, capabilities·transport, 카드 기본값 표시 및 미지원 수단 거절 테스트 | 기본값 적용 표시·capabilities에 따른 UI 설계 |
| D-02 미합의 | 부산 전역 목표, 첫 주 해운대 한 권역·축소 조건 제안 | FR-007~009·018, 권역 필터·지원 필드, 미지원 조건 422 검수. Must 완료로 기록하지 않기 | 실제 표본 확인·누락률 조사, 가상 응답 화면 검수 |
| D-03 미합의 | 원본 단일 source와 초안 sources/sourceIds | FR-012·020, DB 출처 관계, Place·Source 매핑, 응답 출처 ID 연결 검증 | 출처·이용조건 수집 양식 준비 |
| D-04 미합의 | 건강 원문 분석과 범주값만 외부 전송하는 정책의 충돌 | NFR-003·008, 전처리·외부 전송·보관 설계, 로그·TTL 폐기 시험 | 가상 입력으로 평가 설계, 민감 원문을 로그에 쓰지 않는 구조 |
| D-05 미합의 | 계획서 SQLite 또는 PostgreSQL, 설계 PostgreSQL/PostGIS | 저장소 구현·적재 명령·좌표 검색 시험. 외부 API 계약 변경은 필요성 확인 후 별도 제안 | Repository 입출력과 데이터 매핑 정의 |

그 밖에 UNKNOWN 접근성 포함, 영유아와 유모차 구분, 부분 수정 충돌, LLM 재시도 시간 예산, 단일 worker/공유 TTL 문제는 02번의 검토 목록을 유지한다. 이후 확정 기록에는 결정자·날짜·선택안·영향 요구사항·API·테스트를 함께 남긴다.

## 3. 바로 사용할 착수 작업 목록 — 제안

담당은 사용자 지정 역할을 유지했다. 순서는 의존성이며 달력상의 확정 마감일이 아니다. GitHub 이슈로 옮길 수 있는 목록이고 실제 이슈는 생성하지 않았다.

| 순서 / 작업 | 담당·관련 요구사항 | 선행 입력 | 완료 기준 |
|---|---|---|---|
| 1. 범위·계약 검토 및 저장소 연결 | 김세민 + 전체 / 전체 FR | 이 기록, 실제 팀 GitHub URL·현재 소스 위치 | D-01~05 선택 또는 유보 기록, 공유 계약 버전 식별, 브랜치·PR 검토 규칙 확인 |
| 2A. 첫 권역 실제 표본 조사 | 이찬용 / FR-007·008·012·020 | 공식 데이터 후보와 사용 가능한 접근 방식 | 원본 ID·좌표·제공기관·URL·기준일·조회일·이용조건 및 누락 필드 기록. 운영시간 등 필수 검증 가능성 평가; 20~30개는 목표이지 완료 수량 아님 |
| 2B. 공통 모델·세션·오류 구현 | 김영무 / FR-001·002·006, NFR-003·008 | 계약 검토 결과·실제 코드 환경 | 5개 API 모델, no-store, 30분 TTL, 원자적 revision, 실패 시 상태 불변. 실제 테스트로 입증 |
| 2C. 가상 예시 화면 연결 | 배진호 / FR-004~006·011·012·018 | 기존 예시·capabilities | 채팅·조건 카드·결과 및 READY/NEEDS_INPUT/후보 부족/오류 표시. 가상 표시, 순차 요청·revision 관리 |
| 2D. 검수 입력과 정답 준비 | 김세민 / FR-002~009·018 | 계약 의미 및 지원 범위 | 가상 입력 10개에 추출 값·HARD/SOFT·질문·거절 기대값 작성, 개발 담당 교차 검토 |
| 3. 실DB·실LLM 연결 | 이찬용 → 김영무 / FR-002·007·009·012 | 2A·2B 및 모델·데이터 이용조건 확인 | 실제 레코드 적재 재현, AIService가 조건만 추출, DB 장소 ID만 선택, 규칙 엔진 시간 계산·검증 |
| 4. 첫 전체 연결 검수 | 배진호 + 김영무, 김세민 검수 / FR-001~012·018 중 지원 범위 | 2C·2D·3, 지도 설정 | 실제 입력→조건 확인→DB 코스→지도·타임라인·이유·출처, 실패 흐름 재현·결과 기록 |

첫 구현 단위는 2B의 공통 모델·세션·오류로 제안한다. 실제 팀 소스가 있으면 그곳의 환경·규칙을 먼저 확인해 이어서 구현하고, 별도 앱을 중복 생성하지 않는다. 2A·2C·2D는 서로 기다리지 않고 진행할 수 있다.

## 4. 인수 테스트 초안 — 아직 실행하지 않음

| ID | 연결 | 입력·상황 | 기대 결과 |
|---|---|---|---|
| AT-01 | FR-001·006 / sessions, chat, profile | 세션 생성 후 chat(expected=0), PUT(expected=1) | 201 생성, 성공 revision 1→2. 이후 courses에는 2 전송 |
| AT-02 | FR-004 / chat | 방문 날짜·시간 없는 가상 입력 | NEEDS_INPUT, 질문 1~2개. 임의 날짜로 READY 처리하지 않음 |
| AT-03 | FR-002·003·006 / chat | 기존 시간 지정 후 “카페는 빼줘” | 기존 시간 유지, 제외 조건 반영. “꼭 카페일 필요는 없어”와 구별 |
| AT-04 | FR-006 / profile, courses | 오래된 revision, 생성 도중 프로필 변경 | 409. 실패한 변경은 상태·revision을 변경하지 않음 |
| AT-05 | FR-007~009 / chat, profile | 배포 capabilities가 지원하지 않는 비어 있지 않은 조건 | 422 UNSUPPORTED_CONSTRAINT. 조건 삭제·일반 코스로 전환 금지 |
| AT-06 | FR-007·009 / courses | 시간 내 후보 두 곳 미만 | 200 INSUFFICIENT_PLACES, course=null. 필수 조건 완화 금지 |
| AT-07 | FR-008·009·012 / courses | 필수 검증값 누락, 없는 장소 ID, 출처 ID 누락, 이동시간 부족 | 잘못된 SUCCESS 방지. UNKNOWN을 무료·접근 가능·상시 영업으로 변환하지 않음 |
| AT-08 | FR-002 / chat | LLM 실패·불확실한 조건 해석 | 503 AI_UNAVAILABLE 등 계약 오류, 조건 카드 입력 안내, 기존 상태 보존 |
| AT-09 | NFR-003·008 / 세션 | 30분 비활동·세션 종료 | 상태 폐기, 만료 요청 410. 원문·프로필·키·세션 토큰의 로그/영구 저장 여부 검사 |
| AT-10 | FR-011·012·018 / UI·courses | 실제 부산 데이터로 친구 동행 코스 생성 | 타임라인·마커·동행 반영·출처·미검증 항목 표시. 방문 순서 선을 실제 보행 경로로 표기하지 않음 |

AT-09의 명시적 세션 종료 서버 통지 방식은 현재 5개 API에 없으므로 추가 설계 사항으로 남긴다. 브라우저 종료만으로 서버 메모리가 즉시 폐기된다고 가정하지 않는다.
성능 목표(추출 5초·생성 15초 등)와 전체 평가 세트(추출 30·수정 20·코스 10)는 01번 기준을 유지하며 첫 주 10개 입력으로 대체하지 않는다.

## 5. 완료·미완료 및 다음 대화용 기록

- **완료 / 2026-10-27:** 제공 소스·로컬 자산·실행 환경 점검, 기존 계약 검사, 문서 JSON 동기화 검사 및 재실행 스크립트 추가, 착수 작업·검수표 작성.
- **제안 / 2026-10-27:** 실제 저장소를 확인한 뒤 공통 모델·세션·오류부터 구현. 데이터 표본 조사·프론트 가상 화면·평가 입력 준비 병행.
- **미합의:** D-01~05 및 명시적 세션 종료 처리. API 초안이나 첫 주 축소 범위를 팀 확정·최종 요구사항 완료로 승격하지 않음.
- **미완료:** 앱 구현·실데이터 확인/적재·실LLM·지도·HTTP 통합·전체 평가·GitHub 협업 증빙. 다음 구현에 필요한 외부 정보는 실제 저장소 URL 또는 기존 소스 위치이며, API 키는 채팅으로 요청하지 않고 실행 환경에서 설정한다.
