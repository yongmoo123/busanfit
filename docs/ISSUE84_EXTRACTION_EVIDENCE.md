# #84 High 추출 근거 검사

관련: FR-002·004·018, AI-REQ-06 / DEC-006·021·022. API 형식·모델·재시도·capabilities는 유지한다.

## 처리 범위

LLM 출력이 타입·업무 스키마에 맞더라도 원문에 근거 없는 값을 포함할 수 있다. `AIConditionExtractor`가 성공 출력을 세션 정책에 넘기기 전에 `extraction_evidence.ground_high_risk_fields`로 검사한다. 원문·정규식 매치·건강 상세를 결과·세션·로그·DB에 새로 보관하지 않는다.

- **EX-14**: 종료 근거 없이 생성한 timeWindow는 전체를 null/UNSET/HARD로 제거한다. 기존 TimeWindow는 시작·종료가 모두 필요한 필드이므로 부분 객체나 종료 기본값을 만들지 않는다. 시간 변경 의도가 있으면 미확인으로 표시해 기존 질문 경로로 보내며 코스 생성은 PROFILE_INCOMPLETE로 차단한다.
- 종료 근거는 명시적 시간 범위(`부터`, `~`, `-` 등), `시각까지`, 또는 시작 시각+명시적 기간이다. 부정한 종료 표현은 긍정 근거로 쓰지 않는다. 이 가드는 완전한 자연어 시간 파서가 아니며 날짜 보존(EX-26)이나 종료 값 자체의 전체 정확도를 해결했다고 주장하지 않는다.
- **EX-31**: 가족 type을 유지하면서 count·hasInfant를 완성 profile.companions와 부분 companionHints 양쪽에서 검사한다. 인원은 단일 명시적 사람 수와 일치해야 유지한다. 명/사람·셋이/넷이 등을 읽고 시각의30분을 인원으로 보지 않으며 여러 집단 수의 합계를 추측하지 않는다.
- 영유아 여부가 미언급이면 true/false 모두 제거한다. 명시적 동반/부재와 충돌하는 출력은 미확인 질문으로 보낸다. `아기자기한`은 동반 근거가 아니다. 일부 정보만 남으면 companions=null/UNSET과 부분 힌트로 전달하므로 count1·hasInfant=false의 가짜 완성 객체가 정책을 우회하지 못한다.
- 원문에 가족이라는 글자가 있어도 LLM의 명시적 비가족 유형(SOLO/FRIENDS/COUPLE/OTHER)은 보존한다. 유형이 없고 가족 표현이 있거나 유형이 FAMILY인 경우만 가족 하위 필드 검사를 적용한다. 카드 PUT은 사용자 명시 입력 경로이므로 이번 가드는 LLM 성공 추출 경계에 적용한다.

## 유지하는 정책

- **DEC-022**: 가족·아이에서 영유아 여부가 없으면 질문1회. 답하지 않고 다음으로 넘어갈 때만 기존 서버의 기본 처리·영유아 안내 경고를 적용한다. 이는 최초 LLM의 추측 false를 수락하는 것과 다르다. 인원 미입력만으로 반복 질문하거나1명을 만들지 않는다.
- 명시적 영유아 답변은 기존 유모차 DEFAULT/HARD 정규화로 전달한다. 기존 USER 이동제약은 보존하고 동행 인원을 만들지 않는다.
- 기존 USER 시간·동행을 근거 없는 AI 값으로 덮지 않는다. 부분 시간 변경은 기존 값을 보존하면서 다시 묻는다. 무관한 메시지로 만들어진 AI 시간은 제거하되 기존 시간에 새 질문을 만들지 않는다.
- 도보·SOLO/COUPLE 등 기존 서버 기본값, 실패 규칙 대체·타임아웃·재시도는 변경하지 않는다.
