# 코스 배치·검증 — 김영무
FR-009 / COMP-05·07의 스케줄러·검증기를 구현했다. #22 후보 검색·도보 이동시간은 외부 포트로 주입하며 실제 검색·거리 공식·DB 구현은 하지 않았다. [#23 구현·검증 기록](../../../docs/ISSUE23_COURSES_IMPLEMENTATION.md)을 따른다.

- `scheduler.py`: 후보 최대 20개, 방문 최대 6곳의 재현 가능한 배치. 모든 시작 후보와 유효 prefix를 비교하고 체류·이동·영업시간·대기를 반영한다.
- `validator.py`: Repository 장소 ID/현재 사실·시간창·운영 구간·반경·제외 카테고리·항목별 접근성·부상 10분 구간·초안 구조를 검증한다. 이동시간을 확인하지 못한 구간은 사용할 수 없다.
- `open_hours.py`: PR #15의 정규화 요일별 구간을 사용한다. 표시 문자열을 운영시간 근거로 파싱하지 않는다. 휴무·미확인·휴게시간·야간 영업·24:00을 구분한다.
- `presentation.py`: 검증된 장소/출처와 최소 템플릿 설명만 기존 응답으로 변환한다. 시간 합계를 계산하며 가격 UNKNOWN과 실제 경로 UNVERIFIED를 보존한다.
- `fakes.py`: 명시적인 가상 Repository·Retriever·고정 이동시간. 공간 질의·SQL·실제 거리 계산을 하지 않으며 일반 앱에서 자동 사용하지 않는다.

`application/course_service.py`가 조회→Repository 사실 재조회→배치→검증→최대 3회 교체·재배치→응답을 제어한다. 출처 조회 중 장소 사실이 바뀌는 경우도 마지막에 재검사한다. 안전하게 배치한 장소가 두 곳 미만이면 course=null/INSUFFICIENT_PLACES다. 장애를 빈 후보로 바꾸지 않는다.

앵커·부분 수정·동행별 가중치·본격적인 추천 이유·조정 제안은 각각 #29·#32·#27·#25·#26 후속이다. 동행 가중치는 임의로 확정하지 않는다. 기본 SOFT 실내 선호의 이진 우선순위와 scorer 주입 지점만 제공한다.
