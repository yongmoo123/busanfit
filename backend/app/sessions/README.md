# 세션 — 김영무
FR-001·006, NFR-003·008의 일부 구현. 전체 요구사항 완료가 아닙니다.
인메모리 TTL 30분, 생성 revision=0, 성공 변경만 원자 증가, 충돌 409·만료 410. POST /api/sessions 및 PUT /api/sessions/{sessionId}/profile에 연결했습니다.

후속 업무 흐름은 `begin(session_id, expected_revision)`으로 복사본을 얻고, 검증을 마친 프로필·이력은 `commit_profile`로 함께 반영합니다. 저장소는 프로필 스키마 검증을 대신하지 않습니다. LLM/DB 호출은 저장소 잠금 밖에서 수행합니다. 코스 생성 완료 시 `finish_read`로 revision을 다시 확인합니다. 실패한 작업은 TTL·프로필·이력·revision을 변경하지 않습니다.
성공 commit/finish만 TTL을 갱신합니다. 만료 시점부터 접근을 거절하며 요청이 없어도 기본 1초 간격으로 저장소 참조를 제거합니다. 종료 시 저장소를 비웁니다. 세션 토큰을 아는 요청을 사용하는 임시 세션이며 사용자 계정 인증을 구현한 것은 아닙니다.

세션 작업 제한은 60초당 20회입니다. 생성은 ASGI 접속 IP 기준 60초당 20회, 최대 세션·IP 버킷 각 1,000개로 제한합니다. 생성 제한 수치는 개발용 기본 정책이며 팀 확정 사항이 아닙니다. 초과 시 429와 Retry-After를 반환합니다. 단일 프로세스용이며 여러 worker/서버 사이에 공유되지 않습니다.
자동 테스트는 가상 입력으로 응답 계약, TTL 경계, 실패 시 상태 보존, 복사본 격리, 동시 갱신, 요청 제한, 요청 없는 만료 정리·종료 시 폐기를 검사합니다.
DEC-009의 명시적 종료는 DELETE /api/sessions/{sessionId}로 구현했습니다. 단일 잠금 아래 해당 엔트리를 제거하며 없는 세션도 본문 없는 204입니다. 종료는 세션 요청 제한을 소비하거나 TTL을 연장하지 않습니다. 진행 중 commit/finish는 삭제 후 410으로 종료되며 세션을 재생성하지 않습니다. 다른 세션·IP 생성 제한은 유지합니다. 삭제는 저장소 참조 제거이며 진행 중 호출이 가진 복사본을 강제 회수하거나 메모리를 보안 덮어쓰기하는 기능은 아닙니다. 다중 worker 지원은 미구현입니다. 세션 토큰·건강 원문은 영구 저장/로그 금지.
